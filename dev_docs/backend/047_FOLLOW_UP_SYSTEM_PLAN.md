## 1. Executive Summary & Architecture Overview

In conversational commerce and appointment-based businesses (salons, clinics, detailing, consulting), **over 60% of potential leads drop off mid-conversation** — they ask about price, get distracted, forget to pick a time slot, or hesitate to confirm.

The **KVIK Follow-Up System** is an autonomous, event-driven retention engine that:
1. **Detects Conversational Inactivity:** Identifies when a client goes silent after expressing interest.
2. **Executes Smart Contextual Nudges:** Dispatches warm, natural follow-ups generated by the AI engine or pre-approved templates.
3. **Respects Channel Windows:** Strictly complies with Meta 24-hour policies on WhatsApp (Cloud API/WABA) and Instagram Direct.
4. **Governs Quiet Hours:** Prevents night-time messages (21:30 – 09:00 in `Asia/Almaty` UTC+5).
5. **Adaptive Appointment Reminders:** Dynamically adjusts reminders based on booking advance notice ($\ge 48\text{h}$ rule) without redundant directions or spam.
6. **Automated 2GIS Review Growth:** Converts completed visits into public reviews by dynamically generating direct 1-click review URLs (`.../tab/reviews/addreview`).
7. **Automates Funnel Progression:** Auto-disqualifies unresponsive leads (`DEAL_LOST` with `lossReason = UNRESPONSIVE_AFTER_FOLLOWUP`) after 3 failed attempts, keeping the CRM clean.

## 2. Meta Channel Restrictions Matrix: WhatsApp WABA, Instagram Direct & Telegram

### 2.1. The Critical Question: *Do Meta channels allow follow-ups? Don't they block messages after 24 hours?*

**Direct Answer:**  
Yes, Meta imposes strict **24-hour messaging windows**, but **follow-ups ARE fully possible and compliant** when handled through the right channel-specific strategy.

| Channel | 24-Hour Active Window (From Last User Msg) | After 24 Hours (> 24h) | Cost / API Rules |
|---|---|---|---|
| **WhatsApp (Cloud API / WABA)** | **FREE-FORM ALLOWED**<br>AI can send 100% dynamic, personalized text, slot offers, questions. | **BLOCKED FOR FREE-FORM**.<br>Must send **Pre-Approved Meta Message Templates (HSM)** (e.g. Marketing / Utility re-engagement). | Template message fee per conversation category (Marketing/Utility). Once client replies, a **new 24h window opens** for AI! |
| **Instagram Direct (Graph API)** | **FREE-FORM ALLOWED**<br>AI can send personalized responses, slot reminders, questions. | **STRICTLY BLOCKED** for automated outbound marketing. Sending standard API messages returns `Error 10 / Outside of allowed window`. | Automated marketing templates are not available for cold re-engagement after 24h on Instagram. Multi-channel fallback (WhatsApp) or Manager intervention used. |
| **Telegram (Bot API)** | **UNLIMITED**<br>No 24h window restriction. | **ALLOWED** at any time until user blocks bot (`/stop`). | 100% Free, zero template restrictions. |

### 2.3. Instagram Direct Follow-Up Strategy

Because Instagram does not support cold HSM template broadcasts after 24 hours, KVIK applies a **3-tier Instagram strategy**:

1. **Tier 1 (Within 24h — Dynamic AI Nudges):**
   * **Step 1 (+2h after silence):** Friendly contextual question (*"Айдос, подсказать по свободным окошкам к мастеру Анне на завтра?"*).
   * **Step 2 (+20h to +22h — The "Last Call" Nudge):** Sent just before the 24h window closes (*"Айдос, держим за вами предварительное время до конца дня. Забронировать?"*).
2. **Tier 2 (After 24h — Cross-Channel Phone Bridge):**
   * If the lead provided their phone number earlier in chat (saved in `Lead.phone`), the system seamlessly routes Step 3 (+48h) via **WhatsApp Template (WABA)** or SMS!
3. **Tier 3 (After 24h — In-App Manager Alert):**
   * If no phone is known, the system assigns a CRM task to the manager dashboard: *"Instagram 24h window expired. Lead went silent on step: QUALIFIED."*

### 3.2. Campaign 2: Adaptive Appointment Reminder Sequence (Post-Booking)

> [!IMPORTANT]
> **The 48-Hour Advance Notice Rule for 24-Hour Reminders:**
> If a client books an appointment **25 hours ahead** (e.g. booked Monday 13:00 for Tuesday 14:00), sending a "24-hour reminder" at Monday 14:00 (just 1 hour after booking) is absurd and annoys the customer.
> 
> **Core Principle:**
> The **24-hour attendance confirmation reminder** (`startTime - 24h`) is **STRICTLY SCHEDULED ONLY IF the appointment was booked at least 48 hours in advance** ($\text{startTime} - \text{createdAt} \ge 48\text{ hours}$, e.g. 2–7+ days ahead).

#### 1. Adaptive Timing Matrix:

```
Advance Notice Time Delta (startTime - bookingCreatedAt):
├── Case A: Advance Booking (Delta ≥ 48 Hours, e.g. booked 2 to 7+ days ahead)
│   ├── 1. Immediate Booking Confirmation (sent instantly upon create_booking)
│   ├── 2. Attendance Confirmation Reminder (sent 24h before startTime)
│   └── 3. Final Short Nudge (sent 2h before startTime)
│
├── Case B: Moderate Advance Booking (3 Hours ≤ Delta < 48 Hours)
│   │   (e.g. booked 25h ahead, 30h ahead, tomorrow, or earlier today)
│   ├── 1. Immediate Booking Confirmation (sent instantly)
│   └── 2. Final Short Nudge (sent 2h before startTime)
│   └── [24h Reminder is SKIPPED: Client just confirmed the booking recently!]
│
└── Case C: Last-Minute Booking (Delta < 3 Hours)
    ├── 1. Immediate Booking Confirmation ONLY
    └── [All intermediate reminders are SKIPPED]
```

#### 2. Concise, Non-Redundant Reminder Copy Rules:
- **Never repeat long address, parking, or contact info** if already discussed in the active chat.
- Keep the reminder **extremely concise** (1–2 sentences):

| Reminder Type | Eligibility & Timing | Clean Copy (No Redundant Directions) | Actions on Reply |
|---|---|---|---|
| **Immediate Confirmation** | All bookings (sent immediately on creation) | *"Записали вас на стрижку к мастеру Анне на 19 сентября в 14:00. Будем рады вас видеть!"* | Confirms record in DB. |
| **24h Confirmation** | **Only if booked $\ge 48\text{h}$ in advance** (sent 24h before `startTime`) | *"Здравствуйте, Айдос! Напоминаем о вашей записи завтра в 14:00 к мастеру Анне. Подтвердите, пожалуйста, визит (ответьте «Буду» или «Перенести»)."* | • "Буду" $\rightarrow$ keeps `CONFIRMED`<br>• "Перенести" $\rightarrow$ launches slot picker |
| **2h Final Nudge** | Bookings made $\ge 3\text{h}$ in advance (sent 2h before `startTime`) | *"Айдос, ждем вас сегодня в 14:00 к Анне!"* | Quick reassurance without spam. |

#### 2GIS Review URL Generator Logic:
```typescript
// src/common/utils/url.util.ts
export function build2GisReviewUrl(raw2GisUrl?: string | null): string | null {
  if (!raw2GisUrl) return null;

  // Clean trailing slashes or sub-tabs
  let base = raw2GisUrl.trim().replace(/\/+$/, '');
  
  // Remove existing /tab/... suffixes if present
  base = base.replace(/\/tab\/.*$/, '');

  // Append direct review creation tab
  return `${base}/tab/reviews/addreview`;
}
```

## 4. Production Edge Cases & Failure Handling Matrix

Follow-up automation can easily annoy customers if edge cases are not strictly handled. Here is the enterprise failure resolution matrix:

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                   EDGE CASE RESOLUTION MATRIX                                    │
├───────────────────────────────────┬──────────────────────────────────────────────────────────────┤
│ SCENARIO                          │ SYSTEM BEHAVIOR & SAFEGUARDS                                 │
├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ 1. User replies while follow-up is│ Instant cancellation. Webhook handler resets follow-up state │
│    scheduled                      │ and cancels pending BullMQ jobs for this conversation.       │
├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ 2. Night Time Quiet Hours         │ Blackout between 21:30 and 09:00 (Asia/Almaty). If a job     │
│    (21:30 – 09:00)                │ lands at 23:00, execution is postponed to next day 09:15.    │
├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ 3. Manager Intercepts Chat        │ If `Conversation.status === MANAGER_INTERCEPTED`, all        │
│    (`MANAGER_INTERCEPTED`)        │ automated follow-up dispatches are paused indefinitely.      │
├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤

├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤

├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ 7. Meta API Rate Limits or Token  │ Worker retries up to 3 times with exponential backoff        │
│    Expiration                     │ (10s, 30s, 60s). Emits error alert to workspace admin.       │
```

## 5. AI Prompt Engineering & Context Assembly for Follow-Ups

To ensure follow-up messages do not sound like spammy robotic reminders, the AI engine is provided with:
1. The **exact context** of why the conversation paused.
2. The **customer's stated preferences** (desired service, master, car model).
3. Strict tone and length constraints (1–2 sentences, warm, zero pushiness).

### 5.1. The Dynamic Follow-Up Prompt Builder

```typescript
export function buildFollowUpPrompt(params: {
  leadName?: string | null;
  historySnippet: string;
  stepIndex: number;
  delayHours: number;
  businessName: string;
  clientProfile?: string | null;
}): string {
  const { leadName, historySnippet, stepIndex, delayHours, businessName, clientProfile } = params;

  const toneInstructions =
    stepIndex === 1
      ? 'Мягко напомни о себе, предложи помощь с выбором времени или ответь на возможные сомнения. 1 вопрос в конце.'
      : stepIndex === 2
      ? 'Вежливо покажи заботу: упомяни, что график заполняется, и предложи 1-2 конкретных удобных варианта.'
      : 'Короткое и вежливое прощальное сообщение (break-up). Уточни, отложить ли вопрос на будущее.';

  return `Ты — персональный менеджер компании "${businessName}".
Клиент ${leadName ? `по имени ${leadName}` : ''} общался с нами ${delayHours} часов назад, но не завершил запись.

ДАННЫЕ О КЛИЕНТЕ:
${clientProfile || '(Данных о предпочтениях пока нет)'}

ПОСЛЕДНИЕ СООБЩЕНИЯ ДИАЛОГА:
${historySnippet}

ЗАДАЧА:
Напиши 1 короткое (максимум 2 предложения), искреннее и естественное сообщение для мессенджера.
ЦЕЛЬ: ${toneInstructions}

СТРОГИЕ ПРАВИЛА:
1. Никаких шаблонных фраз вроде "Напоминаем вам" или "Вы не ответили".
2. Обращайся по имени, если имя известно.
3. Отталкивайся от того, о чем конкретно шла речь в диалоге (услуга, дата, мастер).
4. Пиши на том языке, на котором писал клиент (русский / казахский).`;
}
```

## 8. Anti-Hallucination & Implementation Master Checklist

To ensure precise, defect-free backend implementation without architectural hallucinations:

- [ ] **1. Meta Window Compliance Check:**
  - [ ] WABA Cloud API adapter checks `TimeUtil.diffInHours(now, conv.lastUserMessageAt) < 24`.
  - [ ] If $> 24\text{h}$, automatically routes via `sendTemplateMessage` instead of `sendTextMessage`.
  - [ ] Instagram adapter halts automated text if $> 24\text{h}$ and triggers cross-channel WhatsApp fallback or manager task.
- [ ] **2. Quiet Hours (Night Blackout) Enforcement:**
  - [ ] Check time in `Asia/Almaty` timezone (`TimeUtil.now()`).
  - [ ] If between `21:30` and `09:00`, calculate delay offset to `09:15` next morning and postpone BullMQ job.
- [ ] **3. Strict 48h Advance Notice Rule for 24h Reminders:**
  - [ ] Check `booking.startTime - booking.createdAt >= 48 hours` before scheduling 24h reminder.
  - [ ] If booked $< 48\text{h}$ ahead (e.g. 25h, tomorrow): Skip 24h reminder completely (only send 2h nudge).
  - [ ] If booked $< 3\text{h}$ ahead (last minute): Send immediate confirmation only; skip intermediate reminders.
  - [ ] Reminders must not repeat static address/parking dumps if previously sent.
- [ ] **4. 2GIS Direct Review URL Generation:**
  - [ ] Automatically transform workspace 2GIS URL to `.../tab/reviews/addreview`.
  - [ ] Send 2GIS review request +2h after `booking.endTime` when `BookingStatus === COMPLETED`.
- [ ] **5. Strict Cancellation Triggers:**
  - [ ] Webhook receiver on any inbound user message cancels scheduled follow-up jobs for that conversation.
  - [ ] `create_booking` handler cancels all abandonment follow-ups and registers appointment reminders.
  - [ ] `MANAGER_INTERCEPTED` status halts execution in the worker.
  - [ ] Opt-out phrases trigger `disqualify_lead` (`CLIENT_DECLINED`) and purge queues.
- [ ] **6. CRM Funnel Auto-Disqualification:**
  - [ ] After Step 3 fails with 72h total silence, worker calls `LeadsRepository.updateStatus(leadId, workspaceId, 'DEAL_LOST')` with `lossReason = UNRESPONSIVE_AFTER_FOLLOWUP`.
  - [ ] Records audit log in `LeadTimelineEvent` (`changedBy: 'SYSTEM'`).
- [ ] **7. AI Engine Prompt Configuration:**
  - [ ] Dynamic prompt builder crafts ultra-fast, natural, non-robotic copy using active chat context.
- [ ] **8. Idempotent BullMQ Jobs:**
  - [ ] Job IDs constructed with deterministic hash `followup:{convId}:{stepIndex}:{lastMsgId}`.
  - [ ] Worker checks DB record before sending — if `conversation.lastMessageAt !== job.expectedLastMessageAt`, worker drops job immediately.
- [ ] **9. Translation & i18n Rules:**
  - [ ] All API responses return `{ code, message }` envelope.
  - [ ] Translation keys registered in `translation_keys_new.json`.
- [ ] **10. Timezone Safety:**
  - [ ] All business hours, quiet hours, and relative timestamps computed through `TimeUtil` (`Asia/Almaty` UTC+5).
